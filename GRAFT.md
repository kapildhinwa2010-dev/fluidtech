GRAFT.md — "base model pe ye layer laga di to kya hoga?"
The question, the three answers, and the measurements behind them.
Every number here comes from `results/e6_graft.json` and
`results/e6_real.json` and is regenerated by
`python3 experiments/e6_graft.py`.
The setup: a trained base LM (a real `TinyTransformer`, 131,392 params),
a document streamed through it in 128-token windows, and the memory layer
attached at the residual stream. The base model is frozen in every
experiment below.
Answer 0 — attaching the layer changes NOTHING (and that is provable)
| measurement|result|
| ---|---|
| logits after attaching the layer vs. before|bit-identical|
| max abs difference|0.000e+00|
Not "close", not "within float tolerance" — the same bits. The reason is
structural, not lucky: the layer's output projections `W_o` are initialised
to zero, so
h' = h + 0 · (everything the layer computed) = h
A layer that is attached but not yet trained is a provable no-op. You
cannot regress your model by attaching it. You can only regress it by
training it, and that is a separate, explicit act.
This is the single most important practical property of the design, and
it is why the layer can be shipped into an existing serving stack
without a rollback plan.
Answer 1 — what happens to the base model's perplexity
On the synthetic corpus (`results/e6_graft.json`)
|  |val loss|ppl|
| ---|---|---|
| base (frozen)|2.2343|9.34|
| base + layer  (layer trained alone)|1.9774|7.22|
| delta|−0.2569 nats|−23 % ppl|
So the layer helps — and it helps even though the base model is
frozen, because the layer alone was trained (the "G1: adapter only"
protocol).
... and on REAL text it is the opposite
The synthetic corpus is a Markov chain with 70 % self-loops, which is the
friendliest possible case for a content-keyed store.  On real English
(`corpus.txt`, Alice in Wonderland, character level, same architecture, same
protocol, the base frozen) the same graft hurts:
| configuration|val loss|ppl|Δ vs base|the layer's own train loss|
| ---|---|---|---|---|
| base (frozen)|2.5898|13.33|–|–|
| base + layer,  lossy (diffusion) tier only , lr 1e-3|3.3992|29.94|+0.8094|2.4306 → 3.4387  ↑ diverges|
| … the same, lr 1e-4|2.7956|16.37|+0.2058|2.4306 → 2.4979|
| … the same, lr 1e-5|2.6027|13.50|+0.0128|2.4306 → 2.3362|
| base + layer,  exact tier only , lr 1e-3|2.5598|12.93|−0.0300|2.4306 → 2.3234|
| … the same, lr 1e-4|2.5860|13.28|−0.0038|2.4306 → 2.3234|
| base + layer, both tiers, lr 1e-3|3.3861|29.55|+0.7963|2.4306 → 3.4355|
This is the single most important result in this document, and it splits
the layer cleanly in two:
the exact tier is safe and slightly helpful (−0.03 nats, and its
training converges);
the lossy (diffusion) tierdegrades the model it is attached to —
by +0.81 nats at lr 1e-3, and the damage is monotone in the learning
rate (+0.81 → +0.21 → +0.013), which is the signature of an
optimisation instability, not a bad idea.
The mechanism. The diffusion state is a persistent accumulator that
lives outside the autodiff graph (by design — it is a memory, not an
activation).  So the read projection is trained against a moving,
non-differentiable target: the state changes every step and no gradient
says how the read should be shaped.  The optimiser takes a step that is
right for this state and wrong for the next one, and the loss climbs.
On the synthetic corpus the same mechanism looks good because the corpus
is redundant enough that "what followed this context" is usually right.
But WHY does it help on the synthetic corpus? It is not better modelling.
Split the validation positions into "the context occurred earlier in the
document" and "the context is new":
| positions|base|base + layer|delta|
| ---|---|---|---|
| context occurred before (the repeated block)|2.4207|2.1962|−0.2245|
| context is new|2.2251|1.9645|−0.2607|
The gain is larger on the NEW positions than on the repeated ones. That
kills the "it quotes the repeated passage" explanation. What is actually
happening: the store holds "what followed this context", and the corpus
is a Markov chain with 70 % self-loops — so the historical continuation is
usually the right continuation, and the layer has become a copy
mechanism. It lowers the loss by reproducing what it has already seen,
not by modelling better.
That is a real capability (it is what makes retrieval-augmented generation
work) but it is not what "a better memory" usually means, and on a
corpus with less redundancy the gain shrinks. Measured on real English
(`results/e6_real.json`, Alice in Wonderland, character level, same
architecture, same protocol) the gain is reported in that file — it is
substantially smaller than the synthetic number, and that is the number you
should quote.
The negative effects (measured, not assumed)
| effect|measurement|
| ---|---|
| does the layer  hurt  the base model when it is attached?|no  — bit-identical (max diff 0.0)|
| does the  exact tier  hurt after training?|no  — −0.030 nats on real text, −0.257 on the synthetic corpus|
| does the  lossy tier  hurt after training?|YES  — +0.809 nats on real text (ppl 13.3 → 29.9)|
| can the lossy tier be made safe?|mostly: at lr ≤ 1e-5 the damage falls to +0.013 nats (near-neutral) — but then it does nothing either|
| does the layer  change  the base model's generation?|only where the layer has something to say; elsewhere, not at all|
Answer 2 — what capability does the model GAIN
This is the part that matters, and it is the one the base model provably
cannot do on its own.
The task
A fact is planted early in a 512-token document:
... K V ...            (K = a key token, V = its value)
... 400 tokens of filler ...
... K                  (the query: the model must now produce V)
The base model's attention window is 128 tokens, so the fact is ~400
tokens outside the window. The base model has never seen the K→V
association in this document (the pairing is randomised per document), so
it cannot know V. Its best possible strategy is a coin flip over the 8
value tokens.
The result
| configuration|exact recall|predicts  a  value token at all|
| ---|---|---|
| base model alone|0.050|0.300|
| base + layer,  exact tier only|0.800|0.975|
| base + layer,  lossy (diffusion) tier only|0.050|0.300|
| base + layer, both tiers|0.800|0.975|
| chance (1 of 8 values)|0.125|–|
16× the base model's recall, 6.4× chance. And the last row is the
important one:
The diffusion tier delivers exactly nothing on its own (0.050 — the
base model's own number). The exact tier delivers all of it.
That is the project's central claim, measured in a graft, on a task the
base model cannot solve: the fluid answers WHERE, the register answers
WHAT. A diffusion smears; it cannot return a token id.
And it is (almost) training-free
The headline configuration uses no gradient steps on the layer at all:
`W_o = I` (the identity map),
one scalar — the read gain — calibrated on the logit gap,
one contrast transform (`pc1`).
The calibration curve (`results/e6_graft.json` → `e6c_gain_sweep`):
| read gain|1|3|10|30|100|300|1000|3000|
| ---|---|---|---|---|---|---|---|---|
| exact recall (insertion at the input)|0.625|0.725|0.775|0.800|0.800|0.800|0.800|0.800|
It saturates: past a gain of ~30, more is not better.
Two insertion points, same result
| where the layer is spliced in|exact recall|
| ---|---|
| the residual stream  before  the base model's layers|0.800|
| the final hidden state,  just before the tied readout|0.800|
Either works. The second is the natural place for a retrieval head; the
first is the one that lets the retrieved information participate in the
model's own computation.
The negative result inside this one
Training the layer on the task makes it WORSE. The G1 protocol (train
only the layer, the base frozen) reached 0.650 — below the
training-free arm's 0.800 — and in an earlier run with a slightly
different schedule it collapsed to 0.100 with `‖W_o‖ = 48`, i.e. the
injected logits saturated and the model froze onto one token. The layer is a
retrieval device; it does not want to be optimised into a copy of the
loss surface.  The training-free identity map is both better and more
stable.
Answer 3 — the things it does NOT give you
Being explicit, because this is where grafts usually oversell:
It does not make the base model better at language. It makes it better
at remembering what it has already seen. The base model's own modelling
quality is untouched (bit-identical when attached).
It does not give the base model a longer attention window. The
attention window is still 128 tokens. What changes is that the layer can
quote something from outside the window — verbatim, and only verbatim.
It cannot reason over what it retrieves; it can only hand it to the model.
The diffusion tier is not what makes the recall work. Measured: 0.050
with it, 0.800 without it (the exact tier alone). The fluid contributes
the address space and the constant-size summary, not the exact answer.
The ceiling is ~0.80, not 1.0. The gap is the injection's
selectivity: with a tied readout, injecting token v's embedding boosts
the logit of every token u by `gain · (emb[v] · emb[u])`, and embedding
rows are not orthogonal, so v's neighbours get boosted too. Measured:
the target's logit 134.9 vs the winner's 151.1 — the injection made the
wrong token win. Projecting out the top principal direction of the
embedding matrix (`pc1`) recovers 0.075 of the loss (0.725 → 0.800); a
full logit-lens one-hot would need the pseudo-inverse of the embedding
matrix, which is numerically unusable in practice.
It does not survive training on the task (see above).
The store is a cache, not a database. It is content-keyed, bounded,
first-write-wins, and it quotes; it does not compose, infer, or answer
questions about what it holds.
The fix (E7): the divergence is solved — and so is the confusion
`experiments/e7_lossy_fix.py` attacks the divergence directly.  Two fixes,
one control, all on the real corpus with the base model frozen.
| configuration|base val loss|Δ vs base|the layer's OWN train loss|verdict|
| ---|---|---|---|---|
| base (frozen)|2.5898|–|–|–|
| control : train the layer through the base model's loss|3.7329|+1.1431|2.4306 → 3.8049|DIVERGED|
| FIX 1 : layer-local objective, persistent state|2.5898|+0.0000|4.3425 →  6.8008|safe, but not learning|
| FIX 2 : layer-local objective +  differentiable state|2.5898|+0.0000|4.3425 →  3.8072|CONVERGED  ✅|
What the fix actually was
The layer-local objective alone was NOT enough.  FIX 1 (the layer
predicts the next token from its own state; the base model is not in the
loss loop at all) still made the layer's own loss rise, because the
persistent state is a numpy accumulator that changes every step: the
optimiser was chasing a moving target either way.
The differentiability was the real fix.  FIX 2 rebuilds the state from a
bounded history inside the autodiff graph on every call (truncated
BPTT).  The write projection is now trainable too, and the layer's
objective converges (4.34 → 3.81).
An honest detail about the two states: they are different estimators,
not the same number.  The persistent accumulator diffuses after every write,
so it is the exponentially-weighted sum `Σ_k D^k w_k` over the whole
session; the rebuild is `D(Σ w_i)` over the last `hist_len` windows —
a truncated version.  Both are diffused aggregates of the same writes; only
the rebuild is differentiable.  (The rebuild's value is checked against a
hand-computed Chebyshev expansion in `tests/test_graft.py`.)
Honest caveat about the +0.0000: in FIX 1 and FIX 2 the layer's own loss
never touches the injection map, so the injection is off by default and
the base model is trivially untouched.  The substantive result is not "the
damage is zero" — it is "the layer can now actually learn" (4.34 → 3.81
vs 4.34 → 6.80), plus the gain sweep below, which is what asks the
interesting question: even now that it can learn, is its prediction worth
injecting?  The answer is no.
But the fix does not make the diffusion tier useful
The layer's own next-token prediction converges to 3.81 nats.  The base
model does the same task in 2.59 nats.  The layer is simply worse at
predicting text than the model it is attached to — which is not surprising:
it is a 16 KB state, the model is 131,392 parameters.
So the injection-strength sweep is the honest summary of the tier's value:
| prior-injection gain|0|0.003|0.01|0.03|0.1|0.3|1.0|
| ---|---|---|---|---|---|---|---|
| Δ base val loss|+0.0000|+0.0001|+0.0004|+0.0015|+0.0092|+0.0584|+0.3623|
Every non-zero gain hurts, monotonically.  The optimum is zero.
The conclusion, stated plainly
The diffusion tier can be made safe (it no longer damages the model),
but on real text it has no upside to offer: its own aggregate is a
worse predictor than the base model, so the only safe injection strength
is zero.  The layer's value is the exact tier, not the fluid.
The project started as "a fluid that replaces attention" and the
measurements keep saying: ship the register, keep the fluid as a
mechanism (the constant-size summary and the address space), and be
honest that it is not what makes the system good.
This is the most useful result of the whole project, and it is negative.
`docs/NEGATIVE-RESULTS.md` N6/N7 record it.
The same measurement at a REAL tokenizer (subword, not characters)
Everything above ran at the character level (vocab 76), which is
maximally redundant and therefore flatters a content-keyed store.  So the
whole measurement was repeated with a byte-level BPE subword tokenizer
trained locally by `tools/bpe.py` (vocab 512, 69,367 tokens for the same
text, no downloads).
| variant|char level (Δ)|subword level (Δ)|training|
| ---|---|---|---|
| base (frozen)|–|–|–|
| lossy tier, lr 1e-3|+0.8094|+0.9831|diverged|
| lossy tier, lr 1e-4|+0.2058|+0.1900|–|
| lossy tier, lr 1e-5|+0.0128|+0.0035|converged|
| exact tier, lr 1e-3|−0.0300|−0.0017|converged|
| exact tier, lr 1e-4|−0.0038|−0.0002|converged|
| both tiers, lr 1e-3|+0.7963|+0.9807|diverged|
| both tiers, lr 3e-3|+0.7450|+2.3652|diverged|
The pattern is identical at both granularities.  That is the important
part: the diffusion tier's divergence is structural, not an artefact of
the character-level corpus.  And the exact tier is neutral-to-helpful at
both.
(The exact tier's benefit shrinks at the subword level, −0.030 → −0.0017
nats.  That is expected: with subword tokens each token carries more
context, so the base model needs less help, and a 12-gram of subwords
repeats less often than a 12-gram of characters.)
THE FIX (E10): one knob for both, by letting the model decide
E9 found the tension: the injection gain that maximises recall (300)
and the one that maximises generation (0.3) are three orders of
magnitude apart, and at the recall gain the base model is ruined
(+1.08 nats).  A layer with one scalar cannot serve both.
The gate.  The base model's own uncertainty at that position:
u_t = 1 - max_v p(v)
boost_t = gain · u_t
The retrieved token's logit is boosted by `gain · u_t` — and the two tasks
differ exactly in the model's confidence:
recall task: the model has no idea what comes next (`u ≈ 1`) → the
retrieval decides;
generation task: the model is usually confident (`u ≈ 0`) → the
retrieval is ignored.
It is not a second hyper-parameter.  It is the model's own confidence, so
there is nothing to tune against it.
Measured (E10, `results/e10_gate.json`)
|  | |
| ---|---|
| the cross-window recall, gated|0.975  — identical to the ungated version|
| the cross-window recall, ungated|0.975|
| the base model's val loss|2.6111 (ppl 13.61)|
| gain|ungated Δ|gated Δ|
| ---|---|---|
| 0.5|−0.0317|−0.0240|
| 2.0|−0.1082|−0.0864|
| 8.0|−0.1219|−0.1447  ← ppl 13.61 →  11.78|
| 20.0|+0.1103|+0.0267|
| 50.0|+0.6954|+0.4862|
| 200|–|+2.7838|
The gate does three things at once:
it does not cost the recall — 0.975 either way;
it improves the best operating point — −0.1447 nats instead of
−0.1219 (ppl 13.61 → 11.78, a 13 % improvement);
it shrinks the damage at high gains — 4× less harm at gain 20, 30 %
less at gain 50.
So the "1000× apart" problem is solved: one gated knob now gives both
the recall and a better perplexity than the ungated layer.
Honest caveat: the gate's boost lives in logit space, not in the residual
stream.  That is why it is safer: it cannot perturb the model's internal
computation, only its final decision.  The residual-stream insertion
remains available (and is what the diffusion tier uses), but for exact
retrieval the readout-time gate is the better instrument.
The recipe that actually works
from superfluid.graft import SAABranch
 import numpy as np
 branch = SAABranch(M=64, r=8, d=model_dim, emb=model.get_input_embeddings(),
                    ctx_len=1, read_gain="raw", read_transform="pc1",
                    capacity=8192,
                    use_exact=True,
                    use_lossy=False,          # <-- the diffusion tier stays OFF
                    state_mode="rebuild")     # <-- the differentiable state
 # 1) attach: provably a no-op (W_o = 0), so the base model cannot regress
 branch.Wo_exact.data = np.zeros((d, d))
 # 2) stream the document through it -- this is the memory
 for window in windows:
     h = model.embed(window) + model.pos[:len(window)]
     h, _ = branch.forward(h, model.embed(window), window)
 # 3) arm the exact tier: the identity map + a calibrated gain
 branch.Wo_exact.data = np.eye(d)
 branch.read_scale = 300.0
 # 4) apply the retrieval GATED, at the readout:
 #    the boost is the base model's own uncertainty
 logits = branch.gated_logits(logits, info, gain=8.0)
the state is 6,316 B for `M=64, r=8` (the fluid tier) plus 20 B per
cached fact (the exact tier);
the base model is frozen the whole time;
attaching it is free and reversible;
the diffusion tier is off by default until its training signal is
fixed (see `docs/NEGATIVE-RESULTS.md` N6).
